CryptoFile: cifrado de archivos con AES-256

Integrantes: [completar]
Octubre 2026

CryptoFile cifra cualquier archivo con AES-256-GCM. La clave se deriva de una contraseña con Argon2id y una sal aleatoria, y el resultado se descifra a un archivo idéntico byte a byte. Se usa desde la línea de comandos (cli.py) o desde una interfaz web hecha con Streamlit (app.py). Las dos usan el mismo núcleo criptográfico (cryptofile/core.py), que se apoya en la librería cryptography de Python. No se implementa AES desde cero.

1. Funcionamiento del código

Estructura

ArchivoResponsabilidad
cryptofile/core.pyFormato del archivo cifrado, derivación de clave, encrypt() y decrypt(), errores (AuthenticationError, InvalidFormatError).
cli.pyComandos encrypt, decrypt y sha256. Pide la contraseña sin mostrarla y nunca sobrescribe archivos sin --force.
app.py, i18n.pyInterfaz web (Streamlit) en español e inglés. Procesa todo en memoria y ofrece el resultado como descarga.
tests/25 pruebas automáticas con pytest: ida y vuelta, contraseña incorrecta, archivo alterado, sal/IV distintos y formato.

Flujo de cifrado

  1. Leer el archivo y la contraseña.
  2. Generar con os.urandom (CSPRNG del sistema operativo) una sal de 16 bytes y un nonce de 12 bytes.
  3. Derivar la clave de 32 bytes: Argon2id(contraseña, sal, t=3, m=64 MiB, p=4).
  4. Armar el encabezado de 43 bytes (magic, versión, parámetros de Argon2id, sal y nonce).
  5. Cifrar nombre original + contenido con AES-256-GCM. El encabezado se pasa como dato asociado (AAD).
  6. Escribir encabezado ‖ texto cifrado ‖ tag (16 bytes).

Flujo de descifrado

  1. Leer el encabezado y validarlo: magic, versión y parámetros dentro de rango.
  2. Re-derivar la clave con la contraseña ingresada y la sal y los parámetros guardados.
  3. Descifrar con AES-256-GCM, que verifica el tag sobre el encabezado y el texto cifrado.
  4. Si el tag no coincide, informar el error y no escribir nada.
  5. Si coincide, recuperar el nombre original y escribir el archivo descifrado.

2. Decisiones de diseño

Modo de operación: AES-256-GCM

Elegimos GCM y no CBC+HMAC porque es un modo de cifrado autenticado (AEAD): en una sola operación, con una sola clave, da confidencialidad e integridad. Con CBC+HMAC hay que derivar dos claves, aplicar padding y respetar el orden encrypt-then-MAC con una comparación en tiempo constante. Cada uno de esos pasos es un punto donde se puede cometer un error. GCM no usa padding, así que el texto cifrado mide lo mismo que el original. El encabezado entra como AAD: no se cifra, pero queda autenticado, y alterar cualquier parámetro, la sal o el nonce invalida el tag. ECB queda descartado porque cifra igual los bloques iguales y deja ver patrones del archivo.

Derivación de la clave: Argon2id

La contraseña nunca se usa directo como clave: pasa por Argon2id, el ganador de la Password Hashing Competition y la opción recomendada por la RFC 9106 y por OWASP. Además de lento es memory-hard: cada intento obliga a reservar 64 MiB, y eso encarece mucho un ataque de fuerza bruta con GPU o ASIC frente a PBKDF2. Usamos la segunda configuración recomendada por la RFC 9106 (t=3, m=64 MiB, p=4). Tarda una fracción de segundo por operación y entra en la memoria de un servidor gratuito. La sal es aleatoria y distinta en cada cifrado: dos archivos con la misma contraseña quedan con claves diferentes y no sirven tablas precomputadas.

Los parámetros se guardan en el encabezado, así se pueden endurecer en el futuro sin perder la capacidad de descifrar archivos viejos. Al leer un archivo se acotan (memoria ≤ 1 GiB, t ≤ 10, p ≤ 16), para que un archivo manipulado no fuerce a reservar recursos desmedidos antes de llegar a verificar el tag.

IV / nonce

El nonce de GCM es de 96 bits, el tamaño estándar, y se genera aleatoriamente en cada cifrado. En GCM es crítico no repetir nunca un par (clave, nonce). Acá además cada cifrado usa una clave distinta, porque la sal es nueva, así que una repetición es prácticamente imposible.

El archivo trae todo lo necesario para descifrarlo salvo la contraseña. También cifra el nombre original, así el descifrado lo restaura y el nombre no queda expuesto. El costo total es de 43 + 2 + largo del nombre + 16 bytes.

Errores

GCM no puede distinguir una contraseña incorrecta de un archivo modificado: en los dos casos el tag no verifica. Por eso el programa informa un único error, “la contraseña es incorrecta o el archivo fue modificado”, y no genera archivo de salida. El descifrado se hace completo en memoria y solo se escribe si la verificación fue exitosa, así que nunca se entrega texto plano sin autenticar. Los archivos que no son de CryptoFile, o que están truncados o tienen parámetros fuera de rango, se rechazan con un mensaje específico antes de derivar la clave.

Limitación conocida. El archivo se procesa entero en memoria. Es la forma más simple de garantizar que no se escriba nada sin verificar, y alcanza para el uso previsto. La interfaz web acepta archivos de hasta 100 MB.

3. Prueba

Ciclo completo con un PDF, comparando el SHA-256 del original con el del descifrado. También se prueba una contraseña incorrecta y un archivo con un solo bit modificado:

$ python cli.py encrypt documento_secreto.pdf
Cifrado OK -> documento_secreto.pdf.cryf (1834 bytes)
$ python cli.py decrypt documento_secreto.pdf.cryf -o documento_descifrado.pdf
Descifrado OK -> documento_descifrado.pdf (1752 bytes)
$ python cli.py sha256 documento_secreto.pdf documento_descifrado.pdf
bb53f8ed9094d50ccf0f5314fff8ef5e05d58ef6a4c7bff0fa75d5665359516c  documento_secreto.pdf
bb53f8ed9094d50ccf0f5314fff8ef5e05d58ef6a4c7bff0fa75d5665359516c  documento_descifrado.pdf
Los hashes COINCIDEN.
$ python cli.py decrypt documento_secreto.pdf.cryf -o x.pdf      # contraseña incorrecta
Error: No se pudo descifrar: la contraseña es incorrecta o el archivo fue modificado.
(código de salida 1 — x.pdf no se creó)
$ python cli.py decrypt alterado.cryf -o y.pdf                 # 1 bit modificado en el byte 100
Error: No se pudo descifrar: la contraseña es incorrecta o el archivo fue modificado.
(código de salida 1 — y.pdf no se creó)

Los hashes SHA-256 coinciden: el archivo descifrado es idéntico al original. Las pruebas automáticas (python -m pytest, 25 passed) verifican además:

  • ida y vuelta byte a byte con archivos de 0, 1, 15, 16, 17, 1024 y ~1 MB;
  • que dos cifrados del mismo archivo con la misma contraseña usen sal y nonce distintos;
  • que la modificación de cualquier región (parámetros, sal, nonce, texto cifrado o tag) se detecte;
  • que la CLI no cree el archivo de salida ante contraseña incorrecta o archivo alterado.

Anexo: ejecución

Requisitos

uv (recomendado) o Python 3.11 o superior con pip. Dependencias (requirements.txt): cryptography ≥ 44, que incluye Argon2id, y streamlit, solo para la interfaz web.

Instalación

Con uv no hace falta instalar nada a mano: uv run lee pyproject.toml y uv.lock, y crea el entorno virtual con las versiones exactas la primera vez:

uv run streamlit run app.py
uv run cli.py encrypt documento.pdf
uv run pytest

Alternativa con pip:

# Windows (PowerShell)
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt

# Linux / macOS
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt

Línea de comandos

# Cifrar (pide la contraseña dos veces, sin mostrarla) → genera documento.pdf.cryf
python cli.py encrypt documento.pdf

# Descifrar → restaura el nombre original, o el indicado con -o
python cli.py decrypt documento.pdf.cryf -o documento_descifrado.pdf

# Comparar hashes
python cli.py sha256 documento.pdf documento_descifrado.pdf

# Ayuda
python cli.py --help

Interfaz web

streamlit run app.py          # abre http://localhost:8501

Arrastrar un archivo a la zona de carga, escribir la contraseña (Enter para aplicarla) y presionar CIFRAR o DESCIFRAR. El botón de descifrar solo se habilita si el archivo tiene el formato de CryptoFile. El resultado se baja con DESCARGAR, junto con su SHA-256. El selector ES/EN cambia el idioma.

Pruebas automáticas

pip install -r requirements-dev.txt
python -m pytest
